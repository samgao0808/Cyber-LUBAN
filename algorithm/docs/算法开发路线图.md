# 四轮校园智能机器车算法开发路线图

## 1. 项目定位与开发边界

本路线图基于项目根目录已有资料制定，包括 `机器车项目介绍.md`、`使用说明.md`、`硬件物品清单.md`。

项目目标是开发网球场、乒乓球场场景下的四轮抓取式智能机器车，核心任务：

1. 网球场、乒乓球场自动捡球。

算法组只负责以下内容：

1. 计算机视觉算法：目标检测、相机标定、像素坐标到车体坐标的三维解算、抓取目标点输出。
2. 自主导航算法：SLAM 建图、定位、全局路径规划、局部避障、视觉目标坐标驱动的动态导航。

算法组不负责以下内容：

1. 底层电机 PID 控制。
2. MCU 驱动程序。
3. 电源、电机、传感器底层接线与硬件电控程序。

上述内容由电控组负责，算法模块只输出导航目标、速度建议、路径点或任务状态，不直接实现底层电机驱动。

## 2. 目录规范

当前项目实际目录为 `algorithm/`，且 `使用说明.md` 中也定义算法模块放在 `algorithm/` 下。后续所有算法相关文件按以下目录存放：

| 目录 | 存放内容 |
| --- | --- |
| `algorithm/src/vision/` | 视觉算法源码，包括目标检测、图像预处理、相机标定、坐标解算 |
| `algorithm/src/navigation/` | 导航算法源码，包括 SLAM、路径规划、避障、定位融合 |
| `algorithm/dataset/` | 视觉训练和测试数据，包括球类、垃圾图像、标注文件、采集视频 |
| `algorithm/models/` | 检测模型权重和训练产物 |
| `algorithm/config/` | 相机参数、检测阈值、模型路径、导航参数、坐标变换参数 |
| `algorithm/test/` | 单模块测试脚本、仿真测试脚本、接口验证脚本 |
| `algorithm/docs/` | 算法设计文档、接口说明、开发路线图、调试记录 |

## 3. 总体开发优先级

开发顺序必须先视觉、后导航、再联调。

1. 第一优先级：视觉仿真模块。
   先在不依赖实车硬件的条件下完成目标检测、相机模型、像素到车体三维坐标解算和可视化验证。

2. 第二优先级：视觉数据闭环。
   建立球类、垃圾目标数据集，完成模型训练、评估和推理接口封装。

3. 第三优先级：导航仿真模块。
   在视觉模块能稳定输出目标坐标后，再开发 SLAM、路径规划、局部避障等导航功能。

4. 第四优先级：视觉导航接口联调。
   将视觉输出的目标三维坐标转换为导航目标点，实现动态目标追踪与路径规划。

5. 第五优先级：实车前算法验收。
   仅验证算法接口、坐标计算、仿真路径和模块稳定性，不写底层硬件控制代码。

## 4. 分阶段开发路线图

2. 在 `algorithm/docs/` 中维护算法路线图、接口文档和调试记录。
3. 在 `algorithm/config/` 中预留视觉与导航配置文件。

存放路径：

| 文件类型 | 路径 |
| --- | --- |
| 路线图文档 | `algorithm/docs/算法开发路线图.md` |
| 视觉配置 | `algorithm/config/vision_config.yaml` |

2. 依赖 `机器车项目介绍.md` 的功能定位。

### 阶段 1：视觉仿真基础框架

优先级：P0，最先开发

目标：在无实车、无真实相机接入的条件下，搭建视觉算法仿真入口，先打通图像输入、目标检测占位输出、坐标解算占位输出、结果可视化流程。

开发内容：

1. 设计视觉模块主流程：读取图像、执行检测、筛选目标、估算目标三维坐标、输出目标列表。
2. 定义标准目标结构，包括类别、置信度、像素框、像素中心点、相机坐标、车体坐标。
3. 支持离线图片和视频输入，便于后续用校园实拍素材测试。
4. 先提供模拟检测器或传统颜色检测器，用于验证坐标解算流程。
5. 输出可视化图片，标注目标框、中心点、估算距离和车体坐标。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 视觉主流程源码 | `algorithm/src/vision/vision_pipeline.py` |
| 检测器接口 | `algorithm/src/vision/detector.py` |
| 坐标解算模块 | `algorithm/src/vision/coordinate_transform.py` |
| 视觉配置 | `algorithm/config/vision_config.yaml` |
| 单图测试脚本 | `algorithm/test/test_vision_image.py` |
| 视频测试脚本 | `algorithm/test/test_vision_video.py` |

验收标准：

1. 输入一张测试图像后，可以输出目标检测结果列表。
2. 每个目标至少包含 `class_name`、`confidence`、`bbox`、`pixel_center`、`camera_position`、`base_position`。
3. 可保存带检测框和坐标信息的可视化结果。
4. 模块不依赖实车硬件，不调用电机控制或 MCU 接口。

依赖关系：

1. 依赖阶段 0 的目录初始化。
2. 不依赖训练模型，初期可使用模拟检测结果或简单颜色检测。

### 阶段 2：相机模型与像素到车体坐标解算

优先级：P0，视觉仿真核心

目标：完成从图像像素坐标到机器人车体坐标系下三维目标点的数学解算，为后续抓取和导航提供统一坐标。

开发内容：

1. 建立相机内参模型，包括焦距、主点、畸变参数、图像分辨率。
2. 建立相机外参模型，包括相机相对车体坐标系的安装高度、俯仰角、偏航角、横向偏移、前向偏移。
3. 完成像素坐标到相机归一化射线的转换。
4. 基于地面平面假设，计算射线与地面的交点。
5. 将相机坐标转换到车体坐标系，输出 `x_forward`、`y_left`、`z_up`。
6. 对网球、乒乓球、垃圾目标分别预留尺寸先验和高度修正参数。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 坐标解算源码 | `algorithm/src/vision/coordinate_transform.py` |
| 相机参数配置 | `algorithm/config/camera_config.yaml` |
| 坐标变换测试 | `algorithm/test/test_coordinate_transform.py` |
| 标定说明文档 | `algorithm/docs/相机标定与坐标解算说明.md` |

验收标准：

1. 给定像素点、相机内参和外参，可以稳定输出车体坐标。
2. 坐标轴定义清晰：车头前方为 `x` 正方向，车体左侧为 `y` 正方向，竖直向上为 `z` 正方向。
3. 对同一目标位置重复计算结果一致。
4. 在仿真标定板或人工构造样例中，坐标误差满足阶段性要求：近距离 0.5 米到 3 米范围内，平面位置误差优先控制在 10 厘米到 20 厘米内。
5. 文档写清楚内参、外参、坐标系和计算公式。

依赖关系：

1. 依赖阶段 1 的视觉输入和目标中心点输出。
2. 后续导航模块必须消费本阶段输出的车体坐标，不直接消费图像像素坐标。

### 阶段 3：球类与垃圾目标数据集建设

优先级：P1

目标：建立适配校园场景的数据集，为后续深度学习目标检测模型训练提供基础。

开发内容：

1. 采集或整理乒乓球、网球、路面垃圾图片。
2. 覆盖不同光照、距离、角度、遮挡、背景和地面材质。
3. 按类别建立标注规范，推荐类别包括 `pingpong_ball`、`tennis_ball`、`trash`。
4. 采用统一标注格式，例如 YOLO 格式。
5. 划分训练集、验证集、测试集。
6. 记录数据来源、采集设备、采集场景和标注规则。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 原始图片 | `algorithm/dataset/raw/` |
| 标注后数据 | `algorithm/dataset/ball_trash_yolo/` |
| 数据集配置 | `algorithm/config/dataset_config.yaml` |
| 数据集说明 | `algorithm/docs/视觉数据集说明.md` |

验收标准：

1. 至少完成一个可训练的数据集子集。
2. 每个类别都有样本，且标注框位置准确。
3. 训练集、验证集、测试集划分明确。
4. 数据集路径不写死在源码中，由配置文件管理。

依赖关系：

1. 可与阶段 1、阶段 2 并行推进。
2. 阶段 4 的模型训练依赖本阶段数据集。

### 阶段 4：目标检测模型训练与推理封装

优先级：P1

目标：训练或微调用于识别球类和垃圾的目标检测模型，并封装为视觉主流程可调用的检测器。

开发内容：

1. 选择轻量化目标检测模型，优先考虑 YOLO 系列，便于后续部署到车载计算平台。
2. 使用阶段 3 数据集完成训练、验证和测试。
3. 输出模型权重、类别文件和训练日志。
4. 封装模型推理接口，输入图像，输出目标框、类别和置信度。
5. 与阶段 2 坐标解算模块连接，形成检测到坐标的完整链路。
6. 支持置信度阈值、类别过滤、最大目标数量等配置项。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 模型推理源码 | `algorithm/src/vision/yolo_detector.py` |
| 模型权重 | `algorithm/models/` |
| 训练配置 | `algorithm/config/train_config.yaml` |
| 推理配置 | `algorithm/config/vision_config.yaml` |
| 模型测试脚本 | `algorithm/test/test_detector.py` |
| 训练记录文档 | `algorithm/docs/目标检测模型训练记录.md` |

验收标准：

1. 单张图片推理能正确识别乒乓球、网球或垃圾目标。
2. 输出格式与阶段 1 定义的检测器接口一致。
3. 模型权重放在 `algorithm/models/`，不放入源码目录。
4. 推理阈值、模型路径、类别名称由配置文件控制。
5. 在验证集上输出准确率、召回率、误检样例和漏检样例分析。

依赖关系：

1. 依赖阶段 3 的数据集。
2. 依赖阶段 1 的检测器接口。
3. 与阶段 2 坐标解算组合后，形成完整视觉仿真模块。

### 阶段 5：视觉仿真闭环与目标点输出

优先级：P0 到 P1，导航前置验收

目标：完成视觉模块闭环，使视觉模块能够稳定输出导航可消费的目标三维坐标。

开发内容：

1. 将检测模型、目标筛选、坐标解算、可视化、结果输出整合为完整流程。
2. 设计目标选择策略，例如优先最近目标、最高置信度目标、指定类别目标。
3. 输出标准结果文件或消息结构，供导航模块读取。
4. 记录视觉帧时间戳和目标坐标，便于导航做动态目标更新。
5. 对异常情况进行处理，包括无目标、目标太远、置信度过低、坐标解算失败。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 视觉主流程 | `algorithm/src/vision/vision_pipeline.py` |
| 目标选择逻辑 | `algorithm/src/vision/target_selector.py` |
| 视觉输出示例 | `algorithm/test/vision_output_samples/` |
| 闭环测试脚本 | `algorithm/test/test_vision_pipeline.py` |
| 接口文档 | `algorithm/docs/视觉导航接口说明.md` |

验收标准：

1. 输入图片或视频后，可以输出目标车体坐标。
2. 视觉输出字段稳定，至少包括 `target_id`、`class_name`、`confidence`、`base_position`、`timestamp`、`is_valid`。
3. 无目标时能够输出明确状态，不导致程序崩溃。
4. 视觉接口文档明确导航模块如何读取目标坐标。
5. 阶段 5 完成前，不启动导航模块核心开发。

依赖关系：

1. 依赖阶段 1、阶段 2。
2. 如果使用深度学习检测器，则依赖阶段 4。
3. 阶段 6 导航开发以本阶段输出为输入条件。

### 阶段 6：导航仿真基础框架

优先级：P2，视觉闭环后启动

目标：在视觉模块稳定输出目标坐标后，建立导航仿真框架，用于路径规划、避障和目标点追踪验证。

开发内容：

1. 定义机器人二维位姿结构，包括 `x`、`y`、`yaw`。
2. 定义地图、障碍物、目标点和路径点数据结构。
3. 实现基础全局路径规划，可先采用 A* 或栅格地图规划。
4. 实现局部避障接口，可先基于简单障碍物距离约束。
5. 预留 SLAM 或定位模块接口，后续接入 Livox Mid-360S、IMU、GNSS 等传感器数据。
6. 导航输出仅为路径点或速度建议，不实现底层电机控制。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 导航主流程 | `algorithm/src/navigation/navigation_pipeline.py` |
| 全局规划 | `algorithm/src/navigation/global_planner.py` |
| 局部避障 | `algorithm/src/navigation/local_planner.py` |
| 地图模块 | `algorithm/src/navigation/map_manager.py` |
| 导航配置 | `algorithm/config/navigation_config.yaml` |
| 导航仿真测试 | `algorithm/test/test_navigation_sim.py` |

验收标准：

1. 给定起点、目标点和障碍物地图，可以输出可行路径。
2. 导航模块能够读取视觉模块输出的目标车体坐标或转换后的地图坐标。
3. 遇到障碍物时可以重新规划或给出避障路径。
4. 没有底层电机控制代码。

依赖关系：

1. 依赖阶段 5 的视觉目标点输出。
2. 不依赖实车底盘控制接口。

### 阶段 7：SLAM、定位与多传感器接口设计

优先级：P2

目标：设计校园场景地图构建和定位模块，为后续实车导航提供算法接口。

开发内容：

1. 结合硬件清单中的 Livox Mid-360S 激光雷达、WITMOTION 惯性传感器、GNSS 天线，设计 SLAM 与定位数据接口。
2. 规划激光雷达点云输入、IMU 姿态输入、GNSS 粗定位输入的数据格式。
3. 在仿真阶段先使用模拟位姿或录制数据验证接口。
4. 输出地图坐标系、车体坐标系、相机坐标系之间的关系说明。
5. 预留后续接入 ROS 2 或其他机器人中间件的接口。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 定位接口 | `algorithm/src/navigation/localization_interface.py` |
| SLAM 接口 | `algorithm/src/navigation/slam_interface.py` |
| 坐标系文档 | `algorithm/docs/机器人坐标系与传感器外参说明.md` |
| 定位配置 | `algorithm/config/localization_config.yaml` |
| 接口测试 | `algorithm/test/test_localization_interface.py` |

验收标准：

1. 明确相机坐标系、车体坐标系、地图坐标系之间的转换关系。
2. 定位接口可以在仿真数据下输出机器人位姿。
3. SLAM 接口不直接绑定某个硬件驱动，便于后续由电控或系统集成环节接入真实数据。
4. 文档明确哪些输入来自硬件驱动层，算法层不实现底层驱动。

依赖关系：

1. 依赖阶段 6 的导航框架。
2. 与真实硬件接入解耦。

### 阶段 8：视觉导航联调

优先级：P2

目标：将视觉目标坐标接入导航模块，实现面向捡球和捡垃圾任务的目标追踪式路径规划。

开发内容：

1. 将视觉输出的车体坐标转换为地图坐标下的目标点。
2. 导航模块根据当前机器人位姿和目标点生成路径。
3. 当视觉目标更新时，导航模块支持动态更新目标点。
4. 设计目标到达判定逻辑，例如进入抓取半径后停止导航并输出抓取准备状态。
5. 输出给电控组的上层指令建议仅包含路径点、目标点、任务状态，不包含底层电机控制实现。

存放路径：

| 内容 | 路径 |
| --- | --- |
| 视觉导航桥接 | `algorithm/src/navigation/vision_target_adapter.py` |
| 联调主流程 | `algorithm/src/navigation/task_navigation.py` |
| 联调配置 | `algorithm/config/task_config.yaml` |
| 联调测试 | `algorithm/test/test_vision_navigation_integration.py` |
| 接口文档 | `algorithm/docs/视觉导航接口说明.md` |

验收标准：

1. 视觉模块输出目标后，导航模块可以生成到目标附近的路径。
2. 目标坐标更新后，路径可以重新规划。
3. 到达抓取触发距离时，输出 `ready_for_grasp` 状态。
4. 对无目标、目标丢失、障碍物阻断路径等情况有明确状态输出。

依赖关系：

1. 依赖阶段 5 视觉闭环。
2. 依赖阶段 6 导航框架。
3. 可在阶段 7 定位接口稳定后增强为地图坐标导航。

### 阶段 9：场景任务策略

优先级：P3

目标：针对两类校园任务制定上层算法策略，使视觉和导航能力服务具体业务。

开发内容：

1. 捡球任务策略：搜索场地、识别球、选择最近球、导航靠近、进入抓取准备状态。
2. 捡垃圾任务策略：巡航、识别垃圾、判断是否可拾取、导航靠近、进入抓取准备状态。
3. 设置不同目标类别的优先级和过滤规则。
4. 记录任务状态机，包括 `searching`、`target_found`、`navigating`、`ready_for_grasp`、`target_lost`、`finished`。
5. 与机械组、电控组约定抓取触发状态，但不开发抓取机构底层控制。

存放路径：

| 内容 | 路径 |
| --- | --- |

| 任务策略文档 | `algorithm/docs/捡球与捡垃圾任务策略说明.md` |

验收标准：

1. 不同场景可以通过配置选择捡球或捡垃圾任务。
2. 任务状态转移清晰，异常状态可恢复。
3. 视觉、导航、抓取准备状态之间接口清晰。
4. 不包含机械抓取机构控制代码和底层电控实现。

依赖关系：

1. 依赖阶段 8 的视觉导航联调。
2. 依赖机械组和电控组提供抓取动作的上层接口约定。

优先级：P3

目标：在实车联调前完成算法模块自测、文档整理和接口交付，降低跨组联调风险。

3. 生成算法接口说明，明确输入、输出、异常状态、配置项。
4. 输出与电控组、机械组的接口边界说明。

## 5. 近期开发建议

近期最优开发顺序如下：

1. 完成 `algorithm/config/camera_config.yaml` 和 `algorithm/config/vision_config.yaml` 的初始参数设计。

3. 开发 `algorithm/src/vision/detector.py` 和 `algorithm/src/vision/vision_pipeline.py`，先用模拟检测框验证流程。
4. 开发 `algorithm/test/test_coordinate_transform.py` 和 `algorithm/test/test_vision_image.py`，建立视觉仿真测试闭环。
5. 开始整理 `algorithm/dataset/`，采集并标注乒乓球、网球、垃圾图片。
6. 在视觉模块稳定输出目标坐标后，再进入 `algorithm/src/navigation/` 的路径规划开发。

## 7. 关键验收里程碑

| 里程碑 | 判断标准 |
| --- | --- |
| M1：视觉仿真跑通 | 输入图片后输出目标框、目标中心点和车体坐标 |
| M2：坐标解算可信 | 像素到车体坐标转换公式明确，近距离误差进入可接受范围 |
| M3：检测模型可用 | 对乒乓球、网球、垃圾有稳定识别结果 |
| M4：视觉输出可被导航消费 | 视觉输出标准目标结构，不再只输出像素信息 |
| M5：导航仿真可规划路径 | 给定起点、障碍物、目标点，可以输出可行路径 |
| M6：视觉导航联调可用 | 视觉发现目标后，导航能规划到目标附近并输出抓取准备状态 |
| M7：实车前交付 | 算法代码、配置、模型、数据、测试、文档完整归档 |
